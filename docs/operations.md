# Operations — FinanceOS

**Version:** 2.0.0 · **Last reviewed:** 23 August 2026

Install, run, build, back up, recover, and clone. Written for the person who owns the
laptop, not for a sysadmin.

---

## 1. Installing the desktop app

The primary form: a real installed program, no browser, no console window, ~12 MB.

### One-time build prerequisites

| Need | Where | Why |
|---|---|---|
| [Node.js LTS](https://nodejs.org) | nodejs.org | Builds the interface |
| [Rust](https://rustup.rs) | `rustup-init.exe`, accept defaults | Compiles the desktop shell |
| [VS Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) | *Desktop development with C++* workload | Rust needs the MSVC linker on Windows |
| WebView2 | Already present on Windows 11 | Renders the interface |

### Build and install

```bash
npm install
npm run desktop:build
```

The installer appears in `src-tauri/target/release/bundle/nsis/`. Run it. The first
build takes a few minutes while Rust compiles its dependency tree; later builds are
quick.

On first launch FinanceOS asks which workbook to use. Point it at your
`Invoice Tracker.xlsx` wherever it lives — it stays there, and the app remembers the
path.

### Development

```bash
npm run desktop        # Tauri window with hot reload
```

## 2. Running in browser mode

For a machine where Rust cannot be installed. Only Node.js is required.

Double-click **`FinanceOS.cmd`**. It installs dependencies and builds the interface on
first run, then starts the local server and opens a chromeless Edge window. Closing the
console window stops it.

```bash
npm start              # same thing manually: build, then serve on :4321
npm run serve          # serve an existing build
npm run dev:server     # API only, restarts on change
npm run dev            # Vite UI on :3000, /api proxied to :4321
```

To use a workbook elsewhere:

```bash
set LEDGER_FILE=D:\Business\Invoice Tracker.xlsx && FinanceOS.cmd
```

To get a Start-menu entry, open the `⋯` menu in the Edge window → **Apps → Install this
site as an app**. The server still has to be running, so keep `FinanceOS.cmd` as the
thing you click — or put a shortcut to it in `shell:startup`.

## 3. Where everything lives

```
Invoice Tracker.xlsx          The database
backups/                      Last 30 snapshots, taken before every write
  Invoice Tracker 2026-08-23T14-22-07.xlsx
Invoice Tracker.saving.xlsx   Only exists mid-write; safe to delete if stranded
dist/                         Built interface (regenerated by npm run build)
src-tauri/target/             Rust build cache (large; safe to delete)
```

The desktop build remembers its workbook path and analytics preference in the webview's
`localStorage`. Neither is data — losing them costs you one file-picker click.

## 4. Backup and recovery

### What the app does for you

Before **every** write it copies the workbook into `backups/` with an ISO timestamp, and
keeps the most recent 30. Writes are atomic: the new file is serialised to
`Invoice Tracker.saving.xlsx` and then renamed over the target, so an interruption
mid-save leaves the previous workbook byte-intact.

### What you should do

The snapshots sit beside the workbook, so they die with the disk. Copy the whole folder
somewhere else on a schedule you are comfortable with — an external drive, or a synced
folder that nothing else writes to. The workbook is a single file; there is nothing
clever to arrange.

### Restoring

1. Close FinanceOS.
2. Rename the bad `Invoice Tracker.xlsx` out of the way (do not delete it yet).
3. Copy the snapshot you want from `backups/` and rename it `Invoice Tracker.xlsx`.
4. Start FinanceOS.

Snapshots are ordinary `.xlsx` files — open them in Excel to check which one you want
before restoring.

### Moving the ledger

Desktop: **Settings → Choose workbook…**, or move the file and re-pick it. Browser mode:
set `LEDGER_FILE`. Take `backups/` with you if you want the history to follow — the app
creates the folder beside whichever workbook it is pointed at.

## 5. Troubleshooting

### "The workbook is open in Excel. Close … and try again."

Excel takes an exclusive lock. Close the file in Excel and retry — nothing was written,
and nothing was lost. The app deliberately does not retry in a loop or write elsewhere.

Reading is unaffected: you can keep the workbook open in Excel while browsing the app,
you just cannot save.

### The app shows old data after I edited the sheet in Excel

Save and close in Excel, then take any action in the app (or reload). Every action
re-reads the file, so the next save will be applied on top of your hand edit rather than
overwriting it.

### "The workbook is no longer at …"

The file moved or the drive is disconnected. Reconnect it, or choose the new location.
FinanceOS will not silently create a replacement.

### Dates look wrong by one day

That class of bug is fixed and pinned by tests — but if you see it, run `npm test`
first. If the date assertions fail, say so with the output; do not "fix" it by shifting
a value.

### `npm run desktop:build` fails

| Symptom | Cause |
|---|---|
| `cargo: command not found` | Rust not installed, or the terminal predates the install — open a new one |
| `link.exe not found` | MSVC build tools missing the C++ workload |
| Fails only on the first run, after minutes | Usually a network timeout fetching crates; run it again |

### Browser mode: "Run `npm run build` first — dist/ is missing"

The interface has not been built. `npm run build`, or just use `npm start`.

### Port 4321 already in use

Another instance is running. Close it, or `set PORT=4322` before starting.

## 6. Health checks

```bash
npm test               # 35 assertions: round trip, legacy parsing, dates, currency
npm run build          # must complete with no errors
```

Then open the app and confirm: the invoice count matches the sheet, the totals match
what you expect, and the workbook still opens cleanly in Excel with dates as dates.

Full manual script: [testing.md](testing.md).

## 7. Upgrading

1. `git pull`
2. `npm install`
3. `npm test` — if the workbook round-trip assertions fail, **stop** and report it
4. `npm run desktop:build`, run the installer

Your workbook is untouched by an upgrade. Take a manual copy first anyway.

## 8. Cloning into a second app

The repo is shaped to be copied rather than extended. A second tool — expenses,
purchase orders, timesheets — is a copy with a different mapping, not a module inside
this one.

1. Copy the folder. `rm -rf node_modules dist src-tauri/target`, then `npm install`.
2. Rewrite the column mapping in `src/lib/workbook.js` — `rowToInvoice`,
   `invoiceToRow`, the sheet names, `DEFAULT_SETTINGS`, and the `mutations`. This is the
   only part that genuinely changes.
3. Rewrite the derived figures in `src/lib/derive.js` for whatever this domain measures.
4. Replace the screens. The `ctx` pattern, drawers, row menu, palette and styles carry
   over unchanged.
5. In `src-tauri/tauri.conf.json` change `productName`, `identifier` and `version`; in
   `Cargo.toml` change `name`. Run `npx tauri icon your-icon.png`.
6. If you will run both in browser mode simultaneously, give the second a different
   `PORT`.

**Resist building a shared framework** for apps that do not exist yet. Two independent
copies are cheaper to run and safer to break than one abstraction serving both — and
when the second app teaches you something, the first is free to ignore it.

## 9. Operational limits

| Limit | Value | What happens beyond it |
|---|---|---|
| Rows | ~50,000 | Whole-file rewrites become slow; move to SQLite behind the same interface |
| Concurrent writers | 1 | Two instances on one workbook overwrite each other silently |
| Request body (browser mode) | 2 MB | Rejected |
| Snapshots retained | 30 | Oldest deleted automatically |
| Currencies | Unlimited | Add a `rate.XXX` row; no code change |

---

## 10. Data ownership

There is no vendor, no account, no export process. The workbook is yours, in a format
every spreadsheet program on earth reads, sitting in a folder you chose. If you stop
using FinanceOS tomorrow, you carry on in Excel with a file that has more columns than
it started with and nothing missing.
